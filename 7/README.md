## Реализация

### Файл `internal/cache/cache.go`

Инкапсуляция логики работы с Redis и предоставление простого API для операций кэширования.

**Ключевые особенности:**
- `Cache` - обертывает Redis-клиент;
- Реализованы методы `Set`, `Get` и `TTL` для основных операций;
- Использован контекст для управления таймаутами операций;
- Поддержка произвольного времени жизни (TTL) через параметр `time.Duration`;
- Обработка ошибок на уровне методов для удобства использования.

**Важные моменты реализации:**
- Метод `Set` позволяет задавать TTL в любых единицах времени;
- Метод `Get` возвращает ошибку при отсутствии ключа;
- Метод `TTL` показывает оставшееся время жизни ключа.

### Файл `cmd/server/main.go`

Создание HTTP-сервера с эндпоинтами для демонстрации работы кэша.

**Особенности сервера:**
- Использование `http.ServeMux` для маршрутизации;
- Валидация входных параметров запросов;
- Корректная обработка ошибок Redis;
- Логирование запуска сервера.

## Ручки

## API Endpoints Documentation

### Базовый URL
`http://localhost:8080`

### Эндпоинты

#### 1. `GET /set`
**Сохраняет значение в кэш на 10 секунд**

Параметры:
- `key` - ключ (обязательный)
- `value` - значение (обязательный)

Пример:
```bash
curl "http://arbond.ru/go/7/set?key=username&value=Alice"
```

Ответ: `Value 'Alice' set for key 'username' with TTL 10s`

URL: **http://arbond.ru/go/7/set**


---

#### 2. `GET /get`
**Получает значение из кэша по ключу**

Параметры:
- `key` - ключ (обязательный)

Пример:
```bash
curl "http://arbond.ru/go/7/get?key=username"
```

Ответы:
- Найден: `Alice`
- Не найден: `Key not found` (404)

URL: **http://arbond.ru/go/7/get**

---

#### 3. `GET /ttl`
**Показывает оставшееся время жизни ключа в секундах**

Параметры:
- `key` - ключ (обязательный)

Пример:
```bash
curl "http://arbond.ru/go/7/ttl?key=username"
```

Ответы:
- Найден: `7` (осталось секунд)
- Не найден: `Key not found` (404)

URL: **http://arbond.ru/go/7/ttl**

## Особенности реализации

**Архитектурные решения:**
- Разделение логики кэша и HTTP-сервера для соблюдения принципа единственной ответственности
- Использование интерфейса `context.Context` для управления временем выполнения операций
- Инкапсуляция Redis-специфичной логики внутри пакета `cache`

**Обработка ошибок:**
- Разделение ошибок "ключ не найден" и "внутренние ошибки Redis"
- Возврат соответствующих HTTP-статусов (404, 500, 400)
- Логирование ошибок на стороне сервера

**Безопасность и надежность:**
- Валидация входных параметров запросов
- Использование дефолтного TTL для предотвращения "вечного" хранения
- Корректное закрытие соединений с Redis при завершении работы

**Производительность:**
- In-memory хранение обеспечивает микросекундную скорость отклика
- Минимальные накладные расходы на обертку Redis-клиента
- Эффективное использование пула соединений библиотекой go-redis
